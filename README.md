# 28卒 ゲーム・CG就活カレンダー

<!-- README.md：このサイトの使い方（更新手順・ローカルでの確認方法・GitHub Pagesでの公開手順）をまとめたファイルです。 -->

大学のゲーム研究会メンバー向けに、28卒（2028年3月卒）のゲーム・CG業界のインターン・本選考の締切を一覧するサイトです。
ビルド不要の静的サイト（素のHTML・CSS・JavaScript）で、GitHub Pages で公開します。

## ファイル構成

| ファイル | 役割 | 更新時に触る？ |
| --- | --- | --- |
| `index.html` | ページの骨組み | 触らない |
| `style.css` | 見た目（色・レイアウト・ダークモード・スマホ表示） | 触らない |
| `app.js` | データを読み込んでタイムライン・詳細・職種の切り替えを作る | 触らない |
| `data/schedule.json` | **日程データ（会社一覧と予定一覧）** | **ここだけ書き換える** |
| `README.md` | この説明書 | 必要なら |

## 日程の更新手順

1. Claude に「○○社の説明会・インターン・選考日程を検索して追加して」「全体を最新にして」などと頼みます。
2. Claude が各社の公式ページなどを確認し、`data/schedule.json` だけを書き換えます。
   - 新しい会社は、先に `companies` に1行足してから、`events` に予定を足します。
   - 先頭の `updated_at` を更新した日にします。
   - 確認した予定は `checked_at` をその日にします。
   - 公式に書かれていない日付は `confidence` を `"要再確認"` か `"前年実績からの推測"` にします（要再確認には ⚠ が付き、推測は最初は隠れます）。
   - 架空の会社・日付は入れません。分からない日付は書かずに、`"open"`（受付中・締切未定）にします。
3. 下の「ローカルでの確認方法」で表示を確かめてから、ブランチを切って PR を出し、マージします。数分で公開ページにも反映されます。

> 個人の選考状況など、メンバーに見せない情報は書かないでください。

### データの全体の形（`data/schedule.json`）

ファイルは「会社一覧（`companies`）」と「予定一覧（`events`）」の2つに分かれています。
会社名は `companies` に1回だけ書き、予定からは会社の `id` で指します。会社名の表記を直すときも1か所で済みます。

```json
{
  "updated_at": "2026-11-11",

  "companies": [
    {"id": "cygames", "name": "Cygames"},
    {"id": "capcom", "name": "カプコン", "url": "https://www.capcom.co.jp/recruit/"}
  ],

  "events": [
    {
      "id": "cygames-winter-1st",
      "company": "cygames",
      "category": "インターン",
      "title": "冬インターン 第1次締切",
      "kind": "deadline",
      "start": "2026-11-27",
      "end": "2026-11-27",
      "time": "10:00",
      "roles": ["デザイン", "TA"],
      "note": "TA・3DCGほか",
      "url": "https://...（この予定の公式ページ）",
      "source": "https://...（日付を確認したページ）",
      "checked_at": "2026-11-11",
      "confidence": "要再確認"
    }
  ]
}
```

### 会社（`companies`）の項目

| 項目 | 必須 | 意味 |
| --- | --- | --- |
| `id` | ○ | 会社を指す短い英小文字の名前（例 `cygames`、`fromsoftware`）。重複不可、後から変えない |
| `name` | ○ | 画面に出す会社名 |
| `url` | | 新卒採用ページなど、会社の情報ページ。予定に `url` がないときはこちらへのリンクを出す |
| `group` | | 合同説明会・イベントの主催（マイナビ、クリ博など）は `"合同"`。画面で「合同説明会・イベント」の見出しの下にまとまる |
| `type` | | 会社の種類（例「コンシューマー大手」「CG映像プロダクション」） |
| `location` | | 主な拠点 |
| `status` | | 28卒の状況（例「2028年度の募集要項を公開済み」） |
| `next` | | 次に見る日程のメモ |
| `roles_note` | | 3DCG・TA関連で確認できた募集職種 |
| `rank` | | 情報ランク。`A`＝28卒の日程を公式で確認済み、`B`＝一部情報や前年の日程あり、`C`＝合同イベント参加などの手がかりのみ |

`type` 〜 `rank` は、会社をタップしたときの詳細に表示されます。予定がまだ1件もない会社は、タイムラインには出ません（`companies` に入れておけば、予定を足したときにすぐ使えます）。

並び順は自由です（画面では締切が近い会社から自動で並びます）。探しやすいように、追加した順か五十音順にしておくのがおすすめです。

### 予定（`events`）の項目

| 項目 | 必須 | 意味 |
| --- | --- | --- |
| `id` | ○ | 予定の一意な名前。`会社id-時期-内容` の形にする（例 `cygames-winter-1st`、`capcom-2028-seminar-1`）。重複不可 |
| `company` | ○ | `companies` の `id` |
| `category` | ○ | 予定の種類：`"説明会"` / `"インターン"` / `"早期選考"` / `"本選考"` / `"イベント"` / `"サークル"`（バーの色が変わる） |
| `title` | ○ | 表示名（例「冬インターン 第1次締切」「ES・作品提出」「会社説明会（オンライン）」） |
| `kind` | ○ | 形：`"deadline"`＝1日の締切（ひし形）、`"span"`＝応募受付期間（塗りつぶしバー。`end` を締切として数える）、`"event"`＝説明会当日・インターン実施期間など（枠だけのバー）、`"open"`＝受付中・締切未定（点線のバー） |
| `start` | ○ | `"YYYY-MM-DD"`。`open` で開始日が分からなければ省略可 |
| `end` | | `"YYYY-MM-DD"`。deadline は `start` と同じ日、1日だけの説明会は省略可、`open` には書かない |
| `time` | | 時刻（日本時間、例 `"10:00"`）。deadline・span では締切時刻 |
| `roles` | | 対象職種。`"デザイン"` / `"TA"` / `"プログラマー"` から選ぶ（3DCG・背景・VFX・CGアーティストなどは `"デザイン"`）。全職種向けの説明会などは3つとも書く |
| `note` | | 補足（例「TAと3DCGは併願不可」） |
| `url` | | この予定の公式ページ。なければ会社の `url` を使う |
| `source` | | 日付を確認したページ（`url` と同じなら同じものを書く） |
| `checked_at` | | 最後に確認した日 |
| `confidence` | | `"確定"`（省略時） / `"要再確認"` / `"前年実績からの推測"` |

#### 1つの選考をどう分けるか

画面では会社をタップすると予定が1行ずつ開くので、**締切や日程が別々のものは別の予定に分けます**。

- 例：インターンの「応募期間（span、インターン）」と「実施期間（event、インターン）」は2件に分ける
- 例：本選考の「エントリー受付（span、本選考）」「ES・作品提出締切（deadline、本選考）」は2件に分ける
- 例：説明会が複数回あるなら、回ごとに1件ずつ（event、説明会）。時刻は `time` に開始時刻を書く

#### 日付が確定していない予定

- 前年の実績から推した時期は `confidence: "前年実績からの推測"`、月だけ分かっているものや日時未掲載のものは `"要再確認"` にし、`note` に「推定時期：2027年3月中旬」のように元の表記を残します。
- 月や「上旬・中旬・下旬」しか分からないときは、その範囲を `start`〜`end` に入れます（上旬＝1〜10日、中旬＝11〜20日、下旬＝21日〜月末）。
- 画面では白抜き・点線・薄い色で描かれ、「次の締切」の計算には入りません。
- `"前年実績からの推測"` は実際の募集ではないので、画面では最初は隠れています。「推測の日程も表示」をオンにしたときだけ、「推測」の印つきで実際の予定の後ろに並びます。サイトは確定した予定を集めるのが中心なので、公式に日程が出たら推測の予定は消して確定の予定に置き換えます。
- 日程が全く分からない予定は `"open"` にして `start` を書かず、`confidence` を `"要再確認"` にすると「日程未定」と表示されます。

#### 職種の付け方

`roles` は `"デザイン"` / `"TA"` / `"プログラマー"` の3つだけです。プランナー、プロジェクトマネージャー、サウンド、ビジネス、コーポレートだけが対象の予定は載せません。全職種向けの説明会・合同説明会は3つとも付けます。

#### 書き間違えたとき

`company` が `companies` にない、`kind` や `category` が上の一覧にない、日付の形が違う、`id` が重複している、などの予定は表示されず、画面の上に「どの予定のどこがおかしいか」が出ます。JSON の書き方自体の誤り（最後の項目のあとにカンマを付ける等）のときは、データ全体が読み込めないというメッセージが出ます。

## ローカルでの確認方法

`index.html` をダブルクリックで開くと、ブラウザの制限でデータを読み込めません。簡単なサーバーを立てて開きます。

1. ターミナル（Windows は PowerShell）でこのフォルダに移動します。
2. 次のどちらかを実行します。
   - Python がある場合：`python -m http.server 8000`（Mac は `python3`）
   - VS Code の場合：拡張機能「Live Server」を入れて、`index.html` を右クリック →「Open with Live Server」
3. ブラウザで <http://localhost:8000/> を開きます。
4. スマホ表示は、ブラウザの開発者ツール（F12）でデバイス表示に切り替えるか、ウィンドウ幅を 760px 以下に狭めると確認できます。

確認用に、URL の末尾に `?today=2026-12-01` のように付けると、その日を「今日」として表示できます。

## GitHub Pages での公開手順

1. このフォルダの中身をリポジトリの直下（`index.html` が一番上にある状態）に置いてプッシュします。
2. GitHub のリポジトリページで **Settings → Pages** を開きます。
3. **Build and deployment** の **Source** を「Deploy from a branch」にし、**Branch** を `main`、フォルダを `/ (root)` にして **Save**。
4. 1〜2分待つと、同じ画面に公開URLが表示されます。これをサークルに共有します。

以降は `data/schedule.json` を更新してプッシュするたびに、自動で公開ページに反映されます。

## 画面の機能

- 上部：「次の締切まであと○日」と、AIの検索による情報なので参考程度にしてほしいという注意書き。
- タイムライン：左に会社名、右に週ごとの目盛り（月曜始まり）。日付の目盛りは画面を下にスクロールしても上に貼り付いたまま見えます。今週の列と今日の位置（点線）に色が付き、次の締切1件は赤で表示されます。
- 会社名をタップすると、その会社の予定が職種と一緒に1行ずつ開き、画面の下に貼り付いた詳細（会社の情報、予定ごとの日時・あと○日・公式ページ・Googleカレンダーに追加）が出ます。詳細は「×」か Esc キーで閉じます。前年実績からの推測は、詳細の中でも実際の予定と分けて最後に出ます。
- 検索欄：会社名・予定名・種類（インターンなど）・拠点・補足のことばで絞り込めます。スペースで区切るとすべてを含むものだけ。全角・半角や大文字・小文字は区別しません。横に表示中の社数・件数が出ます。
- ひし形やバーにマウスを合わせると、詳しい日時が小さく表示されます。
- 横の移動：下のスライダー、マウスでドラッグ、スマホは指でスワイプ。「今日へ」で今週付近に戻ります。
- 職種（デザイン / TA / プログラマー）の切り替えと「推測の日程も表示」（最初はオフ）。終わった予定は常に薄い色で表示し、会社の中ではこれからの予定の後ろに並びます。
- 会社は「企業」と「合同説明会・イベント」に分かれ、それぞれ次の予定が近い順に並びます。日付が推定だけの会社はその後ろ、受付中だけの会社はさらに後ろです。
- 一番下：最終更新日、凡例、注意事項、ライト/ダーク切り替え（常に表示）。
- 日付の計算はすべて日本時間です。
